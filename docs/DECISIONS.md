원래 PRD 전문: https://github.com/Chokoty/KIS-AutoRebalancer/blob/458f622cc3a192be982f9b654bcc55fcfa47f457/PRD.md

## 1. 이 프로젝트는 한국투자증권(KIS) 전용 (2026-09-17)

- 나무증권·토스증권은 이 시트/코드베이스에 넣지 않고 별도 프로젝트로 한다.
- 그래서 잠깐 만들었던 `BrokerClient`(디스패처) + `brokers/KISAdapter` 분리를 되돌렸다(`137cf83`).
  KIS 말고 분기할 곳이 없는데 디스패처를 두면 "나중에 붙일 수 있다"는 신호만 주는 죽은 코드가 된다.
- 나무·토스 API 비교표(인증, 잔고, 주문, 모의투자 유무)는 원래 PRD 6.1절에 있다.

## 2. 보호 예수금은 매수 여력에서만 뺀다

- 수익 실현 후 인출 예정액은 `effectiveBuyPower`에서 차감한다(`40025ec`).
- "보호 예수금이 있으면 자동매매를 통째로 건너뛰기"는 택하지 않았다. 나머지 자산의 정상 리밸런싱까지
  최대 14일 막히는 부작용이 더 크다고 봤다.

## 3. 긴급 대응

- 종목 즉시 전량매도는 원클릭이 아니라 `confirm()`을 한 번 거친다. 잘못 누른 종목이 전량매도되는 게
  더 큰 위험이라고 판단했다.
- 긴급 정지는 "차선유지"(정기 자동매매) 트리거만 끈다. 이 코드베이스에는 AI가 스스로 매매하는 트리거가
  없다(FSD 자율매매는 `27fb10a`에서 빠졌고 V2 코드베이스에만 있다). V2를 합치면 이 범위를 다시 정한다.
- 급할 때 쓰는 메뉴라서 `🚨 긴급 대응`을 메뉴 맨 위(새로고침·리밸런싱 실행 다음)에 둔다.

## 4. 자동 새로고침은 30분 시간 트리거

- 시트를 열 때마다 도는 `onOpen` 새로고침 대신 30분 간격 시간 트리거를 쓴다(`ensureAutoRefreshTrigger`).
- 이유: 열 때마다 몇 초씩 멈추고, 여러 명이 열면 API를 반복 호출했다.
- 대가: 시트를 열어도 즉시 갱신되지 않는다. 최신 값은 "🔄 새로고침" 메뉴로 본다.

## 5. 알려진 한계

- FSD 드라이빙 모드는 항상 Standard로 동작한다. 모드를 바꾸는 메뉴(`setFSDMode*`)는 `27fb10a`에서 삭제됐다.
- 업데이트 내역 링크는 `window.open()` 대신 사용자가 직접 누르는 링크다. 팝업 차단 때문이다.
